2.2 What the wizard actually writes (real structure)2.2 向导到底写了什么（真实结构）

One custom endpoint — the minimum. Replace the three placeholders only:单个自定义端点——最小形态。只替换三个占位符：

# ~/.hermes/config.yaml — minimal custom endpoint
model:
  provider: custom
  default: YOUR-MODEL-ID
  base_url: https://your-endpoint.example.com/v1
  api_key: ${YOUR_KEY_ENV_NAME}

Reusable named providers — the pattern that scales. Define each endpoint once under providers: with key_env (the name of the env var, not the secret), then select with custom:<name>:可复用的命名提供商——能规模化的写法。每个端点在 providers: 下定义一次，用 key_env 写变量名（不是密钥本身），再用 custom:<名字> 选中：

# ~/.hermes/config.yaml — named providers (keys stay in ~/.hermes/.env)
providers:
  mylab:
    api: https://llm.internal.example.com/v1
    key_env: MYLAB_API_KEY
    transport: chat_completions
  together:
    api: https://api.together.xyz/v1
    key_env: TOGETHER_API_KEY

model:
  provider: custom:mylab
  default: YOUR-MODEL-ID

# ~/.hermes/.env (values live ONLY here, one per line)
MYLAB_API_KEY=sk-YOUR-KEY-HERE
TOGETHER_API_KEY=sk-YOUR-KEY-HERE

Optional: fallback chain and auxiliary models. Fallbacks engage on 429/529/503/connection failure; auxiliaries (compression, titles, vision) can each point at a cheaper or vision-capable model. Keep the primary working before adding these.可选：fallback 链与辅助模型。Fallback 在 429/529/503/连接失败时启用；辅助任务（压缩、标题、视觉）可各自指向更便宜或支持视觉的模型。先调通主模型再加这些。

# append to ~/.hermes/config.yaml only after the primary works
fallback_providers:
  - provider: custom:mylab
    model: YOUR-FALLBACK-MODEL-ID
    base_url: https://llm.internal.example.com/v1
    key_env: MYLAB_API_KEY

auxiliary:
  compression:
    provider: custom:mylab
    model: YOUR-CHEAP-MODEL-ID
    base_url: https://llm.internal.example.com/v1

3.2 Production-grade index: separate pgvector database3.2 生产级索引：独立的 pgvector 数据库

Why separate? Hermes MCP (gbrain serve) and dashboard-triggered syncs run concurrently — PGLite's single-writer lock fights that. A small local Postgres with pgvector (Docker, ARM64 image) removes the contention and keeps embeddings available. This database is different from WorkDash's Postgres in Chapter 4.为什么要独立？Hermes MCP（gbrain serve）和面板触发的同步是并发跑的——PGLite 单写锁会打架。本地起一个带 pgvector 的小 Postgres（Docker ARM64 镜像）即可解决，还能用 embedding。这个库与第 4 章 WorkDash 的 Postgres 是两个库。

AGENT PROMPT · 智能体提示词

"Give GBrain its own pgvector Postgres on my Mac: start pgvector/pgvector:pg16 (ARM64) on 127.0.0.1:55432 with a stored password, point gbrain at it (gbrain init --prefer-postgres or the documented ladder), re-run sync + embed --stale over ~/brain, and prove concurrency: leave `gbrain serve` running while a second shell runs `gbrain sync --repo ~/brain`. Report `gbrain stats` page/chunk counts and both commands' exit statuses."

COMMAND · 可执行命令

  -p 127.0.0.1:55432:5432 -e POSTGRES_USER=gbrain \
  -e POSTGRES_PASSWORD='CHANGE-ME-STRONG' -e POSTGRES_DB=gbrain \
  pgvector/pgvector:pg16
gbrain init --prefer-postgres
gbrain sync --repo ~/brain --yes && gbrain embed --stale
gbrain stats

3.3 Wire GBrain into Hermes (stdio MCP, read-focused)3.3 把 GBrain 接入 Hermes（本机 stdio MCP，读为主）

Hermes spawns gbrain serve as a local subprocess — no server, tunnel, or token. The canonical command below performs a live handshake at add time and then asks Enable all N tools? [Y/n]: pipe Y in non-interactive runs, keep --args last (everything after it becomes server argv), and never trust the add command's exit code — it returns 0 even on failure.Hermes 把 gbrain serve 当本地子进程拉起——不需要服务、隧道或 token。下面这条标准命令在添加时就会做真实握手，然后问 Enable all N tools? [Y/n]：非交互运行时用管道传 Y；--args 必须放最后（它后面的都会被当成服务端参数）；永远不要信这条命令的退出码——失败它也返回 0。

COMMAND · 可执行命令

printf 'Y\n' | hermes mcp add gbrain --env GBRAIN_HOME=$HOME --connect-timeout 60 \
  --command "$(which gbrain)" --args serve
hermes mcp list   # row must read: gbrain ... enabled (with a tick)
hermes mcp test gbrain  # must exit 0 and print the discovered tool list

Resulting block in ~/.hermes/config.yaml (what “wired” looks like — keep the tool list read-only):成功后 ~/.hermes/config.yaml 里会出现这一段（“接好”长这样——工具列表保持只读）：

mcp_servers:
  gbrain:
    command: gbrain
    args: [serve]
    env: { GBRAIN_HOME: /Users/YOUR-NAME }
    connect_timeout: 60.0
    enabled: true

AGENT PROMPT · 智能体提示词

If either fails, show the failing output and the mcp_servers block — do not claim success on exit code alone. Fix PATH first if `which gbrain` is empty in Hermes' environment (export ~/.bun/bin)."

4.4 Live GBrain freshness: tiny macOS sync hook (or manual sync)4.4 GBrain 实时新鲜度：小而美的 macOS 同步钩子（或手动同步）

Every dashboard write-back can POST {"reason":"write-back"} to GBRAIN_SYNC_HOOK_URL (3s timeout, debounced; unset = safe no-op). Prefer manual sync if you would rather keep fewer processes.面板每次写回都会向 GBRAIN_SYNC_HOOK_URL 发 POST {"reason":"write-back"}（3 秒超时，防抖；不设就是安全的空操作）。极简 Mac 跑下面这个只绑回环、防抖的小钩子即可——实现同样的 POST /sync 契约，不带生产环境的健康/(best)/systemd 全家桶。想少跑进程就选手动同步。

COMMAND · 可执行命令

cat > ~/brain-sync-hook.py <<'EOF'
#!/usr/bin/env python3
"""Loopback-only debounced gbrain sync hook for Mac (minimal tutorial).
POST /sync {"reason": "..."} -> runs gbrain sync+embed once after 10s quiet."""
import json, subprocess, threading, time
from http.server import BaseHTTPRequestHandler, HTTPServer
PENDING = False; RUNNING = False; LAST = 0.0; RESULT = "never_run"
def worker():
    global PENDING, RUNNING, LAST, RESULT
    time.sleep(10)
    while True:
        PENDING = False
        try:
            r = subprocess.run(["/bin/bash","-lc",
                "export PATH=\"$HOME/.bun/bin:$PATH\"; gbrain sync --repo $HOME/brain --yes && gbrain embed --stale"],
                timeout=1800, capture_output=True, text=True)
            LAST = time.time(); RESULT = "ok" if r.returncode==0 else f"exit_{r.returncode}"
        except Exception as e:
            LAST = time.time(); RESULT = f"error: {e}"[:200]
        if not PENDING:
            RUNNING = False; return
        time.sleep(10)
class H(BaseHTTPRequestHandler):
    def _j(self, s, o):
        b = json.dumps(o).encode(); self.send_response(s)
        self.send_header("Content-Type","application/json")
        self.send_header("Content-Length",str(len(b))); self.end_headers(); self.wfile.write(b)
    def do_POST(self):
        global PENDING, RUNNING
        if self.path.rstrip("/") == "/sync":
            ln = int(self.headers.get("Content-Length") or 0)
            if ln: self.rfile.read(ln)
            PENDING = True
            if not RUNNING:
                RUNNING = True; threading.Thread(target=worker, daemon=True).start()
            return self._j(202, {"status":"scheduled"})
        return self._j(404, {})
    def do_GET(self):
        if self.path.rstrip("/") == "/status":
            return self._j(200, {"ok":True,"last_result":RESULT,"last_completed":LAST})
        return self._j(404, {})
    def log_message(self,*a): pass
HTTPServer(("127.0.0.1",9103),H).serve_forever()
EOF
chmod +x ~/brain-sync-hook.py
python3 ~/brain-sync-hook.py &  # or: launchd for auto-start (agent can add a plist)

# docker compose up -d app   # recreate so the app picks up the hook URL

# fallback (simplest): leave GBRAIN_SYNC_HOOK_URL unset and run this after edits:
# gbrain sync --repo ~/brain --yes && gbrain embed --stale
